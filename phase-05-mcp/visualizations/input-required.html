A refund that needs a person: input_required

In the 2026-07-28 revision a server can't call back into the client. When a tool needs a human, it returns a question (resultType: "input_required") plus a signed requestState, and the client retries the same call with the answer. The server remembers nothing in between, so round 2 is untrusted input. Pick a scenario, then step through it.
